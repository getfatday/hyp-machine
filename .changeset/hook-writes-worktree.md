Hook files now land in the checkout the session works in, so they ride the pull request: every hook row resolves its repository through one contract, `hyp_config.resolve_root` (the payload cwd's checkout when it is the project or another checkout of the same repository -- a linked worktree included -- then the process cwd's, then `CLAUDE_PROJECT_DIR`), and the three writers that still fell straight back to `CLAUDE_PROJECT_DIR` follow it: `compile-dashboard.py` in hook mode (`--hook`, passed by hooks.json), the license-join advisory (now the Python entry `hooks/scripts/license-join-hook.py` in place of the inline shell), and the `cd` lines of `harden-check.sh` and `leak-status.sh` (which also honour the `HYP_ROOT` the session-start-budget wrapper hands down); `session_resolver.py` and `commit-backstop.py` take the root from the payload instead of an argv `CLAUDE_PROJECT_DIR`. The files those writers touch get a merge shape from `/hyp:init` (`templates/gitattributes`): the ledger and `.claude/leak-meter-fires.log` merge by union (one self-contained JSON object per line, newline-terminated, carrying its date -- `append_line` refuses a multi-line row and repairs a missing final newline; `scripts/merge-attrs-check.py` lints it, `ADVISORY-36 merge-attributes` at session start), and `DASHBOARD.md`, `decisions.html` and `ledger/north-stars/*.html` are derived (`merge=binary -diff linguist-generated`): regenerated after a merge -- `compile-dashboard.py <root>`, `git add DASHBOARD.md decisions.html`, `git commit --no-edit`; a north-star page by `compile-north-star-progress.py --all --repo <root>`, `git add ledger/north-stars`, `git commit --no-edit` -- never merged by lines. Why: the maintainer observed on 2026-09-12 that per-hook files were written to the root of the repository the plugin was installed in rather than the session worktree, so ledger updates were lost or conflicted; the lab lane H-DRAFT-b9e771b2-hook-writes-worktree pinned the environment contract from five real sessions (a session that enters a worktree after launch keeps `CLAUDE_PROJECT_DIR` at the launch checkout while its hooks run in the worktree) and its baseline reproduced the leak on the released 0.26.0 (`DASHBOARD.md`, `decisions.html`, the license-join corpus, symlink and fires log written into the main checkout). What a consumer does: re-run `/hyp:init` once per repository (it appends the missing `.gitattributes` rows and never removes yours) or copy the rows from `templates/gitattributes`; `docs/upgrading.md` carries the regeneration sequence. What is written is unchanged, only where; a plain checkout receives exactly the released path set (regression: `scripts/selftest-worktree-root.py` 31 checks, `scripts/selftest-merge-safe-files.py` 21 checks). To undo, revert the merge commit of this release.
